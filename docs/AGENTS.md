# AGENTS.md — docs

Documentation is product here.

## Audience

Write for:
- Swift developers
- Apple-platform developers
- local AI builders
- open-source readers with no private context about Split or 2tap

## Documentation rules

- prefer plain, strong English
- avoid inflated AI-framework language
- explain *why* before *how*
- keep the Apple-native angle concrete
- show how this differs from Karpathy's autoresearch without pretending to replace it

## Most important docs

- `README.md`
- `IMPLEMENTATION_PLAN.md`
- `vision.md`
- `architecture.md`
- `split-receipt-lab.md`

## Good docs

Good docs make a reader think:
"I understand the thesis, I understand the loop, and I can imagine using this in my own Apple-native AI app."
